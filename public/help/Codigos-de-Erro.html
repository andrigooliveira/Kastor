Códigos de erro do reWork

O que cada código HTTP significa nesta plataforma, quando aparece, e como resolver. Cobre erros que o cliente vê como toast, mensagens no console do navegador e códigos que aparecem no log do servidor.

01Como ler os erros

Todas as respostas de erro do reWork seguem o formato:

{ "error": "Mensagem legível em português" }

O cliente mostra um toast vermelho com essa mensagem quando a chamada falha. No console do navegador, aparece a linha do log com GET/POST /api/... → NNN onde NNN é o código HTTP. No servidor, cada request é logada como MÉTODO /caminho → NNN Xms.

i
Onde ver os logs Cliente: F12 → aba Console. Servidor: terminal onde o node server.js roda (ou docker logs em prod).

02Famílias de código HTTP

Os códigos são agrupados por primeiro dígito:

FaixaSignificado
2xxSucesso — o servidor aceitou e processou a requisição.
3xxRedirecionamento — o cliente precisa ir a outra URL. O reWork raramente usa.
4xxErro do cliente — algo na requisição está errado (dados inválidos, sem permissão, ausente). O usuário/frontend precisa ajustar.
5xxErro do servidor — o servidor sabia o que fazer mas falhou ao fazer. Reportar bug.

Todos os códigos HTTP que o backend do reWork produz hoje, ordenados por frequência aproximada:

400
Bad Request · Requisição inválida
Cliente

O servidor entendeu a requisição, mas o conteúdo é inválido. É o código mais comum no reWork porque cobre toda validação de formulário no backend.

Exemplos frequentes

  • "Nome obrigatório" — campo string vazio onde é required
  • "URL inválida" — webhook com endpoint não-HTTP
  • "Nome muito longo (máx. 60)" — extrapolou tamanho
  • "Data inválida" — prazo fora de YYYY-MM-DD
  • "Selecione ao menos um evento" — webhook sem eventos escolhidos
  • "Squad destino não acessível" — mover pra squad sem permissão
  • "Senha obrigatória" — unlock do cofre sem preencher

Como resolver

Ler a mensagem do toast — ela sempre indica o campo/regra violada. Corrigir e reenviar.

401
Unauthorized · Não autenticado
Cliente

Cookie de sessão ausente, inválido ou expirado. O middleware requireAuth devolve 401 antes de processar a rota.

O que acontece no cliente

O helper api() detecta 401 e chama forceLogout() — redireciona pra tela de login sem mostrar toast (evita ruído em página que só está esperando o cookie).

Como resolver

  • Refazer login
  • Se persistir, checar se o cookie está sendo enviado (F12 → Application → Cookies → verificar fluxo_sess)
  • Verificar TTL da sessão via env KASTOR_SESSION_DAYS (default 30)
403
Forbidden · Sem permissão
Cliente

Autenticado, mas a ação não é permitida pra este usuário. Diferente do 401, refazer login não resolve — falta permissão real.

Casos típicos

  • "Apenas administradores podem fazer isso" — rota adminOnly chamada por não-admin
  • "Apenas moderadores ou administradores podem fazer isso" — rota modOrAdmin chamada por comum
  • "Sem acesso ao squad" — tentativa de ler/editar entidade de workspace onde o user não está
  • "vault_locked" — cofre de senhas travado (destrave primeiro)

Como resolver

Pedir ao admin pra elevar sua role, ou pra te adicionar ao squad. Pro cofre: destravar via senha ou biometria.

404
Not Found · Não encontrado
Cliente

Ou a rota não existe, ou a entidade pedida pelo id não está no cache/DB (foi deletada, ou id errado).

Exemplos

  • "Demanda não encontrada" — abrir um link antigo depois da demanda ser deletada
  • "Cliente/Projeto/Fluxo não encontrado" — mesma coisa pra outras entidades
  • "Credencial desconhecida" — tentar auth com credencial WebAuthn removida

Como resolver

Confirmar o id na URL. Se veio de link antigo, a entidade pode ter sido movida pra Lixeira (admin/mod pode restaurar em /trash). Slugs desatualizados não geram 404 — o parser extrai o id do final da URL.

409
Conflict · Conflito
Cliente

Tentativa de criar/atualizar uma entidade que viola unicidade.

Exemplos

  • "Username já em uso" — cadastro de usuário
  • "Email já em uso" — cadastro de usuário
  • "Esse tipo já existe" — biblioteca de tipos de demanda

Como resolver

Escolher outro valor. Pra recuperar um usuário desativado com o mesmo nome, usar a Lixeira em vez de criar de novo.

413
Payload Too Large · Corpo grande demais
Cliente

O corpo da requisição (JSON, upload) é maior do que o limite configurado no express.json(). O 413 é disparado pelo middleware do Express antes de a rota rodar, então a mensagem vem em texto puro (não no formato { error: ... }).

Limites atuais

RotaLimite
/api/uploads, /api/demands*, /api/demands/:id/comment, /api/me, /api/users*, /api/projects*75 MB
Todas as outras rotas200 KB
Comentário HTML sanitizado (dentro do 75MB)200 KB após limpeza

Causas típicas

  • Anexo/avatar acima de ~50MB (com overhead de base64 vira ~75MB)
  • Muitas imagens inline num único comentário (cada uma pesa depois do resize)
  • PUT em /api/passwords/:id com senha absurdamente grande (>500 chars) — cai na rota leve (200KB) só se não bater no allowlist do jsonLg

Como resolver

  • Comprimir a imagem antes de enviar
  • Reduzir a quantidade de imagens inline no comentário
  • Se realmente precisa aumentar o limite, ajustar em server.js:1047:
    const jsonLg = express.json({ limit: '75mb' });
    Cuidado: RAM do processo escala com o pico de payloads simultâneos
!
Sinal no cliente Como o 413 vem em texto puro, o toast pode mostrar mensagem genérica tipo "Erro 413" ou similar. Checar o console (aba Network) confirma.
415
Unsupported Media Type · Tipo não suportado
Cliente

Upload com MIME fora do whitelist. O reWork bloqueia por segurança:

MIMEs permitidos

  • image/png, image/jpeg, image/gif, image/webp
  • application/pdf
  • Outros formatos comuns (docx, xlsx, txt, zip) — ver ALLOWED_MIME_EXT em server.js

Bloqueados de propósito

  • text/html, application/xhtml+xml — XSS same-origin
  • image/svg+xml — pode carregar <script>
  • application/xml, text/xml — XXE em alguns viewers

Como resolver

Converter o arquivo pra um dos formatos aceitos (ex.: exportar SVG como PNG, HTML como PDF).

429
Too Many Requests · Muitas tentativas
Cliente

Rate limit disparou. O reWork usa buckets por-usuário (fallback pra IP quando não autenticado) em rotas sensíveis.

Rotas com limite

  • Login — 5 tentativas por 5 minutos por IP
  • Cadastro de comentários — proteção contra flood
  • Envio de reset de senha

Como resolver

Esperar o tempo indicado no header Retry-After (o toast mostra os segundos). Depois disso, o bucket zera. Não adianta clicar de novo — cada tentativa recarrega o timer.

500
Internal Server Error · Erro interno
Servidor

Uma exception não tratada rolou dentro de uma rota. Isso é um bug — a rota deveria ter validado antes.

O que fazer

  • Copiar o toast + o URL da tela onde aconteceu
  • Se possível, abrir o console (F12) e copiar o stack trace da chamada /api/...
  • Reportar como issue com passos pra reproduzir

Casos conhecidos

  • Falha ao decifrar entrada do cofre — chave mestra (data/secret.key) foi trocada sem migrar; entradas antigas ficam ilegíveis
  • Falha ao iniciar registro WebAuthn — RP config inconsistente entre begin/finish (mudou de domínio no meio)
502
Bad Gateway · Serviço externo falhou
Servidor

O reWork tentou contatar um serviço externo e recebeu erro ou timeout. Não é problema do reWork — é do endpoint chamado.

Onde aparece

  • Teste de webhook — endpoint Discord/Slack/n8n devolveu HTTP ≥ 400 ou não respondeu em 10s
  • Sincronização Google Calendar — API Google fora do ar ou token expirado
  • Título de link — servidor de origem lento ou bloqueou o fetch

Como resolver

Testar de novo em alguns minutos. Se persistir, checar o status do serviço externo. Pra webhooks, revisar a URL — pode estar mal formatada ou desativada no destino.

503
Service Unavailable · Indisponível
Servidor

O servidor está de pé mas não consegue atender agora. Situações:

  • Postgres inacessível (rede, credencial, container down)
  • Boot ainda em andamento — migração/seed rodando
  • Storage encriptado corrompido

Como resolver

Aguardar alguns segundos e tentar de novo (boot completa rápido). Se persistir por >1min, olhar os logs do container/processo pra ver o erro real.

14Erros de rede (não têm código HTTP)

Quando a requisição nem chega ao servidor, o cliente exibe:

!
"Sem conexão com o servidor. Tenta de novo em instantes." Wi-Fi caiu, o container reiniciou, DNS falhou, ou o browser bloqueou (firewall/proxy). Não é erro HTTP — o fetch nem completou.

Diagnóstico rápido:

  1. Abrir outra aba: se google.com não carrega, é a rede
  2. Tentar recarregar: se a página crua não abre, é o servidor
  3. Ver o console (Network): status (failed) confirma falha de rede

15Erros do Cofre de Senhas

O cofre tem 2 códigos específicos além dos genéricos:

Código / mensagemO que significaComo resolver
403 vault_locked Sessão do cofre expirou (15min de inatividade) ou nunca foi destravada. Cliente devolve pra tela de destravar automaticamente. Digite sua senha ou use biometria.
401 Senha incorreta Unlock com senha errada. Não gera audit entry (evita enumerar). Confirmar a senha. Se esquecer, admin pode resetar no /users.
500 Falha ao decifrar… Chave mestra do disco (data/secret.key) trocou; cipher antigo virou lixo. Restaurar backup do secret.key. Sem isso, as entradas afetadas precisam ser recadastradas.

16Erros de biometria (WebAuthn)

Os endpoints /api/passwords/webauthn/* têm códigos específicos além dos padrão. Também há erros do lado do browser que não chegam ao servidor:

Do servidor

  • "Sessão de registro expirou" — challenge tem TTL de 5min. Recomeçar o cadastro.
  • "Sessão expirou" — mesmo com auth. Reabrir o modal.
  • "Registro não verificado" / "Assinatura inválida" — a resposta do authenticator falhou a verificação FIDO. Geralmente clock drift ou browser bugado; tentar em outro dispositivo.
  • "Credencial desconhecida" — cred foi removida entre begin e finish (raro).
  • "Nenhuma credencial registrada" — tentou destravar sem ter cadastrado nada primeiro.

Do browser (JavaScript)

  • NotAllowedError — usuário cancelou o prompt do OS, ou a operação passou do timeout. O cliente mostra "Cancelado".
  • InvalidStateError — este authenticator já está registrado (o excludeCredentials pegou).
  • NotSupportedError — nenhum authenticator disponível no dispositivo (sem Windows Hello, sem Touch ID, sem chave FIDO).

17Glossário rápido

  • Middleware — camada que roda antes da rota (auth, body parser, rate limit).
  • Rate limit — teto de N requisições em X segundos por chave (usuário ou IP).
  • Payload — corpo da requisição (JSON, arquivo).
  • MIME — tipo declarado do conteúdo (image/png, application/pdf).
  • RP (Relying Party) — o site que confia no authenticator. Aqui é o domínio do reWork.
  • Challenge — valor aleatório que o servidor manda pro authenticator assinar (previne replay).
  • Assertion — a assinatura devolvida pelo authenticator. Servidor verifica com a chave pública guardada.
  • Sanitizador — filtro que remove tags/scripts perigosos antes de aceitar HTML (usado em comentários).
