Basics · 01

Welcome to reWork

reWork is a task management platform for marketing teams and agencies. This manual follows a progressive order — newcomers can read it from start to finish; people who already use it can jump straight to the section they need.

What you can do here

  • Create and follow tasks — every marketing work request becomes a task with a workflow, assignee, due date and full history.
  • See the team's weekly schedule — time blocks, meetings (via Google Calendar) and assigned tasks.
  • Automate the repetitive — to-do lists you can apply to new projects, monthly recurring tasks, Discord integrations.
  • Measure capacity and delivery — dashboard with forecast, delays, throughput and reports by client/project.
  • Keep logins safe — encrypted password vault that unlocks with biometrics.

Basics · 02

Getting started

Sign in, a first look around the screen and how to change the default password. If you already use it, skip to Concepts.

Signing in for the first time

  1. Accept the invite you got by email and create your password (or get a username and a temporary password from the admin).
  2. Open reWork's address in the browser (or the desktop app).
  3. Enter your email or username + password on the sign-in screen, plus the code sent to your email.
  4. You land straight on Home.
!
Change the default password If you got a temporary password, go to Profile → Security as soon as you sign in and set a password of your own. An admin can also reset your password if you forget it.

A tour of the screen

Three fixed areas on every page:

  • Sidebar (left) — team switcher at the top + grouped navigation. On screens < 880px it becomes a drawer opened by the hamburger.
  • Top bar — screen title + active timer (when there is one) + notification bell + + New Task button.
  • Main area — the content of the chosen screen. Filters sit at the top of this area, almost always mirrored in the URL so you can share them.

Change your password

Sidebar → click your name/photo at the bottom → My Profile → Security section. You need the current password to confirm.

Language

reWork follows your organization's language (set by its country). To use another one, go to My Profile → Appearance → Language.

Sign out

Profile → Sign out button. Ends the session in this browser. You stay signed in on other devices.

Basics · 03

Core concepts

Five words that show up almost everywhere. Get comfortable with them before diving into the rest.

Team (workspace)

A slice of the operation — usually a group of clients served by one crew. Each user belongs to one or more teams (admins see all of them). The team switcher at the top of the sidebar filters everything you see: clients, projects, tasks, dashboards.

Many things are per team: clients, projects, workflows, lists. Others are organization-wide: integrations (Discord webhooks), task types, the to-do list library.

Client

A company/brand you serve. It lives inside a team. Each client can have several projects.

Project

A specific effort within a client — "Social Media 2026", "Corporate Landing Page", "Black Friday Campaign". It links tasks to the appropriate workflow. A client with no project still works, but the structure gets shallow.

Workflow

The sequence of stages a task goes through until it's done. E.g.: Briefing → Creative → Review → Approval → Publishing. Each stage has an assignee (by position), an SLA (deadline in days) and an optional checklist. Workflows live inside a client and can be reused across several projects.

Task

The unit of work — a specific request ("banner for event X"). It follows the workflow of the project it was born in and carries due dates, comments, deliverables, attachments, checklist and history. A task is what shows up on the Schedule, on the Kanban and in My Tasks.

i
Rule of thumb Team > Client > Project > Task. A workflow is a recipe applied to the project — several of its tasks follow the same step by step.

Terms that show up later

  • Stage — each step within the workflow. A task is always in one stage.
  • Assignee — who's working on the task NOW. It changes as the task moves through stages (derived from the position).
  • Current stage due date vs Final due date — the first belongs to the stage the task is in; the second is the overall deadline, if any.
  • Area — the user's "function" (Creative, Social Media, Development, etc.). It determines which stages they "pull".
  • Position — hierarchy within the area (Analyst, Director, etc.). Independent from the area.
Daily use · 04

My Profile

Everything about you — photo, contact, personal integrations, language and password. Get there from the bottom of the sidebar (name + avatar).

Photo, name and role

The profile photo accepts PNG/JPG/GIF/WebP. It's optimized automatically so it doesn't eat up storage. Name and area/position are set by the admin when you're added, but you can adjust your display name.

Email for notifications

With a confirmed email, reWork sends important alerts there (mentions, assigned tasks, approvals). You can turn each event type on or off under Notifications.

Discord (personal)

Paste your Discord user ID (not the username). When a webhook posts in the channel tagging you, Discord sends a real notification (sound/badge).

How to get the ID: Discord Settings → Advanced → turn on Developer Mode; right-click your name in the chat → Copy User ID.

Google Calendar

Connects your calendar so reWork pulls your meetings and shows them on the Schedule and on Home.

  1. Profile → Integrations → Connect Google Calendar.
  2. Allow read-only access in Google's popup.
  3. Done: events show up in blue on the Schedule.
i
Read-only reWork doesn't create, edit or delete events in your calendar. It only reads.

How meetings look on the Schedule

  • Solid outline — you accepted the invite.
  • Blue outline — no response yet.
  • Red outline + strikethrough — you declined; it doesn't count as busy time.

Change password

You need the current password to set a new one. At least 8 characters. If you forgot it, use "I forgot my password" on the sign-in screen.

Daily use · 05

Create a task

The + New Task button lives at the top right of every screen. It opens a 4-step wizard that makes sure the task is born in the right place.

The wizard

  1. Client — search or click the card. Only active clients of the current team show up.
  2. Project — same, filtered by the chosen client. If the client has only 1 project, the wizard skips this step.
  3. Task type / Workflow — if the project has a single workflow, it goes straight to the form. If it has several, choose the type (Creative, Social Media, etc.) and the appropriate workflow.
  4. Details — name, briefing, due date, priority, initial assignee, checklist, attachments. Only the name is required.

Daily use · 06

Working on a task

Click a row in the list or a card on the kanban to open the detail. That's where 90% of the work happens. The URL becomes /demands/slug-id — copy it to share a direct link to the detail.

Anatomy of the detail

  • Header — name, client/project/type, and actions in the corner (archive, checklist, history, X).
  • Visual pipeline — numbered dots showing every stage of the workflow. The current one pulses; completed ones are filled in.
  • Central panel — assignee, due dates, workflow, timer, buttons to move the stage forward/back.
  • Side tabs — Description, Checklist, Attachments, Comments, Hours, History.

Pipeline and stages

A task is always in one stage. To move forward: the right arrow button at the bottom (or pick the target stage directly on the pipeline). To go back: the left arrow. Each change is logged in the history with timestamp + user.

When a task enters a stage, reWork:

  • Recalculates the assignee (based on the stage's position)
  • Recalculates the "stage due date" (the stage's SLA from today)
  • Notifies the new assignee (in-app + email + Discord, according to their preferences)
  • Fires the demand.stage webhook to the appropriate integrations

Due dates and priority

Two due dates coexist: the final one (overall deadline) and the current stage one. In lists, the Effective due date field uses the stage's date if there is one, otherwise the final one.

Due date color:

  • Green — in the future, comfortable margin
  • Yellow — due in ≤2 days
  • Red — was due yesterday or earlier (overdue)

Priority 1 is red, 2 orange, 3 yellow, 4 blue. Used as a tiebreaker in sorting and in the dashboard's "Priority" widget.

Checklist

Each stage can have a default checklist (set in the workflow). When the task enters the stage, the default items become checkable items. You can add items specific to this task with the + button.

Deliverables

Pieces, Artwork and Variations are editable counters. They don't affect the workflow; they're reported under Analytics → Reports → Output.

Attachments

Drag files straight into the modal or click + Attachment. Accepted formats: PNG, JPG, GIF, WebP, PDF, DOCX, XLSX, TXT, ZIP. SVG and HTML are blocked for security. The per-file limit depends on the plan (see error 413 if you go over).

Comments

Rich text with formatting:

  • Bold, italic, underline — toolbar buttons or Ctrl/⌘+B/I/U
  • Numbered and bulleted lists
  • Links — the link button opens an inline popover (it doesn't take you off the screen); paste the URL, press Enter
  • Inline images — paste or drag them; they're embedded in the comment's HTML (they don't become attachments).
  • Mentions — type @ to open the user picker. The person mentioned gets an in-app + email + Discord notification.
  • Emoji reactions — click the reaction icon to open the picker; add 👍 or similar without having to reply.

Timer and time tracking

The ▶ button starts a timer. It stays visible in the top bar on every screen (switched task? the timer keeps going). Buttons:

  • Pause/Resume — pausing keeps the time accumulated
  • Check ✓ — log the measured hours
  • X — discard without logging

You can also log hours manually by typing start/end/hours. Logged hours count toward Home, Capacity and the output report.

History

The History tab shows every state change: creation, stage moves forward/back, time entries, field edits, archiving. Each row has timestamp + user. It's an immutable audit trail.

Task list views

On the Tasks page, three ways to see the same data (toggle in the filter):

Table

Sortable columns: name, team, project, client, type, status, assignee, stage due date, priority.

Kanban

Columns by stage OR by attention (On time / Overdue / No due date). Drag cards to move them.

Calendar

Monthly view with colored dots on the days. Click a day to filter the tasks due that day.

Filters — the URL is shareable

Every filter you apply (search, team, client, project, user, period, status) is mirrored in the URL as a query. Applied ?client=abc&status=late? Paste the link in the chat and whoever opens it sees exactly the same filtered view.

When you switch pages, the query is dropped (it makes no sense to carry Tasks filters over to Home).

Bulk actions

Check the box on several rows in the table → a floating bar shows up at the bottom with: assign, change status, delete, and more.

Daily use · 07

My Tasks and Schedule

Two screens designed for "what do I need to do now and in the coming days".

My Tasks

Pre-applied filter: Assignee = you. It's the same engine as the Tasks screen, but focused. You see the weekly schedule embedded at the bottom — blocks, meetings and tasks due soon, all together.

Schedule

Hourly grid per business day (Mon–Fri). Two modes, switched with the toggle:

  • Individual — one user, 1 or 2 weeks visible
  • Team — several users side by side, a single day

Navigation

The < > arrows jump a week/day. The date label is clickable — it opens a mini calendar to jump straight to any day. The Today button goes back to the current one.

Create a block

Drag on an empty time slot → Schedule block modal:

  • Free — a generic block (internal meeting, lunch, focus); it doesn't count toward the working day. Supports recurrence (daily, weekly, monthly, custom).
  • Task — linked to the task; it counts toward the working day.

Edit and move

Drag the block to move it; drag the bottom edge to resize. Click to edit/delete. Recurring blocks ask for the scope when deleting: only this one, from this day on, or the whole series.

Google Calendar

If you connected it (see Profile), your meetings show up in blue. You don't edit them — they're read-only. Accepted meeting time counts toward the working day.

i
Mobile On screens < 640px, the Schedule opens in 1 week by default (2 weeks don't fit in portrait). You can still switch to Team mode (single day), which works better on a phone.

Organization · 09

Clients and Projects

How to add, organize and generate reports for the clients your team serves. Requires moderator or admin permission to create/edit.

Create a client

  1. Menu → Clients → + New Client button.
  2. Fill in the name, industry and avatar (optional).
  3. Choose the team (moderators only see their own teams).
  4. Save. The client shows up in the grid.

Apply a template

If there's already a similar client, use Start from a template when creating — it copies projects and workflows from an existing client template (see Templates). Ideal when you serve several clients with an identical structure.

Exploring the client

Click a card to open the detail:

  • Projects tab — lists the projects, + New Project button.
  • Workflows tab — shortcut to the client's Workflows.
  • Assets tab — useful links (Drive, Notion, etc.) the team shares.
  • Documents tab — briefings, contracts, guidelines.

Projects

A project belongs to a client. It has a name, avatar, default workflow, active/archived status. The project's tasks inherit its workflow (they can be overridden if the project accepts multiple workflows).

The /projects page (not linked in the menu, reachable through Dev Tools) shows the global list of all projects with filters by client/status.

Archive vs. delete

  • Archive — the client/project disappears from the active lists but the history stays intact. Reverting takes 1 click.
  • Delete — goes to the Trash (soft delete). It stays there for 30 days and is purged automatically. While it's in the Trash, an admin/moderator can restore it.

Monthly PDF report

In the client detail, the Report button. Choose the month → it generates a PDF with: cover (logo + name + month), list of projects and completed tasks, hours logged per analyst, deliverables, output chart. Great for closing the month with the client or for internal records.

There's also a Project report (same thing, smaller scope) and the Analytics · Reports dashboard for a view without a PDF.

Organization · 10

Task Workflows

Workflows are the "recipe" tasks follow. They define the stages, who works on each one, how many days each has and what needs to be done.

Where they are

Menu → Task Workflows. A view of client cards (each card = one client + a workflow counter). Click a client to see and edit its workflows. Requires moderator or admin.

Create a workflow

  1. Inside the client → + New Workflow.
  2. Name (e.g. "Instagram static post"), icon (lucide library), task type (dropdown with the organization-wide library).
  3. Add the stages in order: each stage has a name, assignee position, SLA in business days, default description, default checklist.
  4. Save. The workflow can now be used in new tasks of the project that points to it.

About stages

  • Position — uses the assignee's area/position. When the task enters the stage, the "natural puller" is any team user with that position. It can be overridden per task.
  • SLA — in business days. It becomes the stage's deadline. 0 = same day; 5 = one week.
  • Default description — text shown in the panel when the task enters the stage (a "how to do it" tip).
  • Default checklist — checkable items. The task gets an editable copy (it doesn't affect the original workflow).

Task types

The Manage types button opens the organization-wide library (shared across teams). Create/rename/delete here.

!
Orphans The modal has an Orphans (N) accordion at the bottom — it lists "type" values that exist in some workflow but aren't in the library. Two actions: Promote (adds it to the library) or Clear (erases the Type field in every workflow that uses it). Useful to clean up loose strings that clutter the Home filter.

Duplicate a workflow to another project

Workflow detail → Duplicate button. Choose the target client/project. It copies the stage structure + defaults; tasks created afterwards in the target use the new workflow without affecting the original.

Organization · 11

To-do lists and Recurring tasks

Two tools to automate the repetitive: template lists you can apply to projects, and tasks that come back every month.

To-do lists

The To-do lists page. Each list is a collection of items ({name, optional task type}). They're organization-wide — visible to every team.

Apply to a project

On the list card → Apply to a project button. Choose client + project. reWork creates the corresponding items using the project's workflow (or asks if there's ambiguity), anchoring each item's type.

Duplicate

The copy icon on the card. It creates "Original List - Copy" (or " - Copy 2/3/..." if one already exists). It keeps items and settings; you can rename and adjust before applying.

Recurring Tasks

Menu → Recurring Tasks. Each rule has: client, project, workflow, assignee, recurrence, and all the task fields (name, briefing, priority, deliverables). On the scheduled day, the task is created automatically.

i
When to use each To-do list = "when I create a new project of this kind, apply these N items". Recurring = "every X of the month, create this specific task".
Organization · 12

Templates

Two ways to reuse: task templates (a pre-filled form) and client templates (a whole reusable structure).

Task templates

Menu → Templates. Each template keeps a preset of fields: name, briefing, priority, checklist, deliverables. When creating a new task, the wizard offers the template in the last step.

Useful for "standard static post", "final artwork approval", "campaign review" — anything you fill in the same way every time.

Client Templates

The /clients/models page (reachable through the Templates button inside Clients, or through Dev Tools). A template groups a ready-made structure:

  • Projects and their workflows
  • Initial to-do lists
  • Default assets/links

When creating a new client, you choose a template and reWork instantiates everything. It cuts new client onboarding from hours to minutes.

Analysis · 14

Analytics

Tabs on the Analytics page: Capacity (what's coming), Rhythm (the week's pace) and Reports (what already happened).

Capacity

Forecasts the team's workload over the next N days — presets of 7/14/30 days or This month. A custom range is available.

Sub-tabs

  • Team — workload per assignee (forecast hours ÷ capacity). Green = room to spare, yellow = tight, red = overloaded.
  • Project — the same, by project.
  • Client — the same, by client.

Top cards

Total capacity of the period (business days × hours per day set in the organization × N people), open tasks in scope, active people with access to the team.

Team output in the period

Hours logged, unique pieces delivered, artwork, variations — free counters.

Reports

A retrospective view. Filters: workspace, client, project, period. It shows:

  • KPIs — total delivered, on time, late, approval rate
  • Stages unified by name — actual vs. planned average SLA; identifies where tasks spend too much time. If you have "Approval" in several workflows of several clients, it all aggregates under a single bar.
  • Assignee ranking — quantity delivered + quality (% on time).
Administration · 15

Teams and Users

Organizational structure. Teams are managed by admins; all users are managed here. admin

Teams (workspaces)

Menu → Teams. Each team has a name, an identifying color and members (users with access). Members can be in several teams at the same time. Admins see all of them by default.

Team color

It shows up in the sidebar (the colored bar of the active team), in the team switcher pill, and in some views that combine teams. Choose contrasting colors if you serve many teams.

Users

Menu → Users. Grid + table. Columns: name, username, area, position, teams, access level, status.

Invite someone

  1. Invite. Enter the person's email.
  2. Choose the access level (Admin, Moderator, Member or Freelancer).
  3. Check the teams the person can access, and optionally the Area and Position.
  4. Send. The person gets a link by email (valid for 7 days) and creates their own password.

Access levels

LevelCan
OwnerEverything an admin can, plus the organization's settings, plan and billing, and transferring the organization.
AdminEverything in the organization. Creates teams and invites people, edits workflows, accesses Dev Tools, sees the vault history.
ModeratorCreates and edits clients/projects/workflows of the teams they belong to. Sees the vault history. Can invite Members and Freelancers when the organization allows it.
MemberWorks on the tasks of the teams they have access to. Uses the vault. Doesn't edit the structure.
FreelancerOnly the tasks they're on — can move stages forward/back and comment.

Areas and Positions

On the same page, the Team areas table lists all areas with a user count. Positions are independent and defined for the whole organization. Admins edit both.

Deactivate vs. delete

Deactivate keeps the user in the history but they can't sign in and don't show up in dropdowns. Deactivated users can be reactivated with 1 click.

Administration · 16

Integrations — Webhooks

Notify external services when events happen on tasks. Discord has its own format (nice embeds); other services get raw JSON. admin

How it works

Each webhook has:

  • URL — the HTTPS endpoint to post to
  • Format — Discord (embed with title/fields/color) or Raw JSON
  • Events — which triggers fire it (created, stage changed, user mentioned, completed, etc.)
  • Target (optional) — only notifies when the event involves this specific user
  • Scope (optional) — only a specific client/project
!
Organization-wide Webhooks apply to all teams — they aren't filtered by the active team. If you create a webhook while in Team A, it fires for tasks of any team.

Set up Discord

  1. In Discord: target channel → Edit Channel → Integrations → Webhooks → New Webhook → copy the URL.
  2. In reWork: Integrations → + New Integration. Paste the URL, choose the Discord format.
  3. Check the events you care about.
  4. (Optional) Restrict it to a target user or client/project.
  5. Save. Use the Send test button to post a test message.

Real mentions on Discord

If the users involved filled in their Discord ID in the Profile, messages use <@ID> — which triggers a real notification (sound/badge). Without an ID, only the name shows up as text.

Raw JSON

A generic format for Make, n8n, Zapier and internal endpoints. The payload contains: event, the whole task (id, name, status, due date…), project, client, the user who triggered it, timestamp.

Administration · 17

Password Vault

Keeps tool credentials (Google Ads, Meta, client platforms) with AES-256-GCM encryption on disk. Entries are organized in folders; only people with access to a folder see its passwords.

Unlock

Menu → Passwords. Each folder shows up locked. Two ways to unlock:

  • Password — type your reWork account password. It stays unlocked for 15 minutes of inactivity (renewed on every action).
  • Biometrics / PIN — the "Open with biometrics / PIN" button if you registered a device. Windows Hello, Touch ID, device PIN, FIDO2 key.

Add / edit / delete entries

The + New entry button. Fields: Name, Link, Email, Username, Password. The generate random password button creates a strong 20-character password.

In the table, the password shows as ••••••••. The eye button reveals it for 20s (auto-hides) and logs the action in the history. Edit and delete icons on the right.

Register biometrics/PIN

The Access button at the top (only shows up if the browser supports WebAuthn) → Access modal → + Add access method.

  1. Choose the type: Biometrics (fingerprint, face) or PIN (device PIN).
  2. Give it a name to recognize it later ("Work laptop", "Personal iPhone").
  3. Continue → the operating system asks you to authenticate (Windows Hello, Touch ID, etc.).
  4. Authenticated → credential registered. It shows up in the list.
i
Strictly personal Each user only sees and registers their own WebAuthn credentials. Not even admins can access yours. You need to register one on each device/browser you use.

History (admin/moderator)

The History button at the top (visible only to admins/moderators). A modal with an immutable log: who unlocked, viewed, created, edited, deleted what and when. Filters by user and by entry. Colored tags per action.

Attempts to unlock with a wrong password aren't logged (so brute-force attempts can't be enumerated). Details of what was edited (name, password, email, etc.) show up in the Details column.

Security in depth

  • Each password is encrypted with AES-256-GCM before leaving the process memory.
  • The master key lives on the server — losing it makes the passwords unreadable. Back it up.
  • A locked vault returns 403 vault_locked on every read — the client forces you back to the unlock screen.
  • Revealing a password records the access in the history with the entry's name.
Administration · 18

Trash and Dev Tools

Tools that stay in the background: where whatever you delete goes, and a hub for routes that have no menu entry.

Trash

Menu → Trash. Lists everything that was soft-deleted — clients, projects, workflows, tasks, lists — with when it was deleted, by whom, and how many days ago. admin moderator

  • Restore — puts the item back in the normal lists, with all links intact.
  • Delete forever — permanent removal. No way back.

Automatic purge: items stay in the trash for 30 days and are then deleted without manual intervention.

Dev Tools

Menu → Dev Tools. Only admins see it. It's a hub of cards with direct links to routes that:

  • Exist in the router but have no menu entry (e.g. Registered Projects at /projects, Workflow Templates at /clients/models, Error Codes)
  • Are sub-tabs that the menu entry opens on the default one (Analytics · Capacity/Reports, Recurring · Tasks/Lists)
  • Are creation modals — shortcuts to open the new task, new client, new workflow wizard, etc. directly

Routes with friendly names

URLs of clients, projects and tasks use slug + id so they're readable:

/clients/red-cdb89429c3da

Filters as links

Since filters live in the URL, you can bookmark a favorite view: "client X's overdue tasks", "my team's open tasks this month", etc. Paste the URL into your browser bookmarks.

Mobile

Every screen is responsive. The sidebar becomes a drawer below 880px; filters stack; tables get their own horizontal scroll; modals become almost full screen. The Schedule switches to 1 week automatically on screens below 640px. Full feature parity — no screen is blocked on mobile.

Frequently asked questions

Quick answers to the most common questions.

I forgot my password. What do I do?

Use "I forgot my password" on the sign-in screen: we send a link to your confirmed email. If you don't have an email linked, ask an admin for help.

How do I move a task to another team?

Task detail → Edit → change the client. The team comes from the client. You need access to the target team.

Can I delete a task "for good"?

Deleting sends it to the Trash. There, an admin/moderator uses Delete forever. The automatic purge also removes it after 30 days.

A user left the company. What do I do?

Deactivate them in Users (don't delete — you'd lose history). Their tasks stay intact; you can reassign them manually or leave them as they are. If they come back, reactivate them with 1 click.

How is the "assignee" chosen for each stage?

If you didn't override it when creating/editing, it comes from the stage's area/position — the team user with that area and position is notified. If you set it manually on the task, that one stays.

What happens if I delete a client with open tasks?

The client goes to the Trash, along with its tasks and projects. While there, everything can be restored. After 30 days, it's purged for good (everything is lost).

My Discord notifications don't arrive.

Check: (1) you filled in the ID (not the username) in the Profile; (2) the Discord webhook or bot is active; (3) the triggering event involves you (mention, you're the assignee, etc.); (4) you allow direct messages from server members.

How do I see how many hours I logged this month?

Home → the hours goal card. For detail: Analytics → Capacity → the hours logged sub-tab.

Does reWork work offline?

No. Every action needs a network connection to sync with the server. A Service Worker caches the app files so it opens fast, but the data lives on the server. If the connection drops, you see a "No connection" toast.

How do I report a bug?

Use Support in the menu to open a ticket: tell us the URL, what you were doing and the error that shows up. A screenshot helps a lot. If it's a specific HTTP code (401, 413, etc.), the Error Codes documentation explains what it means.
